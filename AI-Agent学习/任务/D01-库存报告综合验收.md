## 业务需求

你要为一家小店生成库存报告。程序读取 `inventory.json` 中的商品记录，成功时把报告保存为另一个文件 `report.json`，并给出简短的成功提示。

一条商品记录包含：

- `name`：非空字符串，只有空白字符也视为无效。
- `quantity`：大于或等于 0 的整数。布尔值、小数和字符串都不算合格的库存数量，例如 `true`、`2.0`、`"2"` 均无效。
- 其他字段可以存在，忽略即可。

输入最外层必须是列表；列表中的每一项必须是符合上述要求的字典。商品名不重复是本题的数据前提，不需要额外编写去重逻辑。

报告需要包含三个字段：

| 字段 | 含义 |
| --- | --- |
| `product_count` | 商品记录总数 |
| `total_quantity` | 所有商品的库存数量之和 |
| `low_stock` | 库存数量**小于阈值**的商品列表，每项仅包含 `name` 和 `quantity`，保留输入顺序 |

初始低库存阈值为 **5**。数量等于阈值时，不进入 `low_stock`。空列表是有效输入，生成两项数量均为 `0`、低库存列表为 `[]` 的报告。

遇到文件不存在、JSON 格式损坏或任意无效记录时，本次报告生成失败：给出能区分原因的提示，不输出误导性的成功信息，不留下半份报告，**不覆盖已有的成功报告**。如果原本没有 `report.json`，失败时也不应新建一份报告。错误提示不要求固定文案；无效记录应能让使用者知道是哪条记录或哪个字段有问题。

不要求一次收集并展示所有错误，发现一个问题后结束本次处理即可。暂不扩展到交互菜单、数据库、并发、文件写入中断恢复或更多业务功能。

## 可复制的输入样例

将以下内容保存为 `inventory.json`：

```json
[
  {"name": "笔记本", "quantity": 8},
  {"name": "签字笔", "quantity": 5},
  {"name": "文件夹", "quantity": 4, "category": "办公用品"},
  {"name": "长尾夹", "quantity": 3},
  {"name": "胶带", "quantity": 0}
]
```

阈值为 5 时，`report.json` 应表达以下内容。JSON 的缩进、键顺序、中文是否转义不影响正确性：

```json
{
  "product_count": 5,
  "total_quantity": 20,
  "low_stock": [
    {"name": "文件夹", "quantity": 4},
    {"name": "长尾夹", "quantity": 3},
    {"name": "胶带", "quantity": 0}
  ]
}
```

输入为 `[]` 时，输出应为：

```json
{
  "product_count": 0,
  "total_quantity": 0,
  "low_stock": []
}
```

## 自测与验收

无需搭测试框架。你先自行选择并运行正常、空列表、阈值边界和至少两类失败情况，说明选择理由。下表为功能检查清单，剩余情况可交教练运行核验；不要求手工逐项填写长报告：

| 情况 | 要验证的行为 |
| --- | --- |
| 正常样例 | 报告内容与上方一致；输入文件未被修改 |
| 空列表 `[]` | 正常生成零统计报告 |
| 阈值边界 | 库存为 4 时计入低库存，5 时不计入；0 是有效库存 |
| 文件缺失 | 给出文件不存在的提示；不改动已有报告 |
| 坏 JSON，例如 `[{` | 给出 JSON 格式错误提示；不改动已有报告 |
| 最外层不是列表，例如 `{}` | 拒绝本次报告生成 |
| 列表项不是字典，例如 `[1]` | 拒绝本次报告生成 |
| 缺少 `name` 或 `quantity` | 拒绝，并提示问题字段或记录 |
| `name` 是空串、全空白或非字符串 | 拒绝本次报告生成 |
| `quantity` 为负数、`true`、`2.0` 或 `"2"` | 分别拒绝这些无效数量 |
| 有额外字段 | 正常处理，报告中不需要带上额外字段 |
| 前面的记录有效、后面一条无效 | 整次失败，不保存前面记录的部分统计 |

检查失败情况时，先保留一份成功生成的报告，确认失败之后其内容没有变化；再检查原本没有报告时，失败不会产生新报告。不要用“程序没报错”代替读取输出文件并核对结果。

正常功能完成后，再做一次需求变更：把低库存阈值从 **5 改成 3**。使用同一份样例，`product_count` 和 `total_quantity` 保持不变，`low_stock` 应只包含库存为 0 的“胶带”；库存等于 3 的“长尾夹”不计入。自行决定怎样组织这项配置，无需为了这个变更新增命令行参数。
