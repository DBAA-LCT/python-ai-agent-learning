# 学习路线：从已有 Python 基础进入 AI 应用

> 2026-09-21 起试行。目标是独立开发、验证和解释可用应用。下列时间是按每周约 11～20 小时安排的参考预算，不是硬性考试期限或就业承诺；根据验收结果调整。

## 当前执行顺序

| 步骤 | 成果与必要知识 | 验收与下一步 | 参考预算 |
| --- | --- | --- | --- |
| D01 综合诊断 | 库存 JSON → 校验 → 报告 → 保存；检验函数、数据结构、文件、异常的组合 | 独立组织核心流程、验证边界和错误、完成阈值变更；通过即开始 A01，局部卡点补后再继续 | 1 次，60～90 分钟 |

## 项目安排

- 主线先做一个小型文档助手，逐步增加功能。先完成一个扎实作品，再根据能力差距与目标岗位决定第二个项目；不要求先凑齐三个同类项目。
- A01 只处理本地文本，暂不加入复杂 PDF/OCR、前端和知识库。接入前选择实际可用的模型服务，核对其当前官方文档；凭证通过环境配置提供，不写入仓库。
- 暂无可用模型接口时，先实现输入输出和可替换调用边界，明确标记模拟结果；实际模型调用仍为未验收项，不因此回到重复语法训练。
- A03 选检索：逐步学习分块、检索、引用和无答案处理，再根据效果决定是否使用 embedding、向量库或 rerank。选工具：先实现一两个明确工具、参数校验、错误处理及调用边界，再考虑框架。
- 每个项目开始给需求和验收标准，让学习者自行组织核心逻辑；对陌生 API 展示短示例，对核心迁移任务保留独立实现空间。

## 用到再补的知识

| 触发需求 | 补充内容 |
| --- | --- |
| 数据模型或模块变复杂 | 类、dataclass、typing、包结构 |
| 需要并发请求或流式响应 | asyncio、异步 HTTP、Streaming |
| 需要查询、持久化或缓存 | SQL 与数据库设计；有明确缓存需求再引入 Redis |
| 需要共享服务或部署 | Linux、Docker、配置、日志、鉴权与接口测试 |
| 检索质量或工具流程需要提升 | Embedding、Rerank、评估、Trace；必要时使用 LangChain/LangGraph |
| 出现跨系统工具需求 | MCP；多 Agent 只在单个流程难以满足需求时考虑 |

这些知识属于长期能力范围，不能因为“以后需要”就全部设成首次应用的前置课。

## 前端与算法

- 保留 React/Next.js 学习目标；默认在首个后端 AI 功能可用且需要界面时启动。先补 JavaScript/TypeScript 与异步，再学 React 状态/组件和 Next.js 路由、服务端边界；不在当前 Python 验收中同时铺开。
- 保留基础算法目标，先结合任务使用列表、字符串和哈希；后续按目标岗位补常见题型。短时复习可以并行，不让每天算法打卡阻塞主线。

## 每周检查与调速

每周只检查三件事：新增了什么可用能力；哪些部分仍靠提示；下一周的一个主要成果是什么。能独立实现和修改就增加任务难度；若卡住，调整相应知识的讲解和任务范围，不无限延长整段基础训练。

4～6 周左右形成一个范围受控原型是试行目标；“原型能运行”“能独立工程化”“具备求职准备”分别验收，不混为一个进度百分比。
