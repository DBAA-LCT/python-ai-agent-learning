### 2026-09-17 — 条件方向和异常类名写错

- **问题：** 为动态录入的成绩数量增加“大于 0”校验。
- **我的做法：** 初次写成 `if 0 <= count`，并使用不存在的 `Value` 异常类。
- **错误：** 合法的正数也进入异常分支，随后产生 `NameError`；条件方向与需求相反。
- **原因：** 没有把自然语言“当数量小于等于 0 时拒绝”转换成对应的逻辑条件，也混淆了 `ValueError` 的完整类名。
- **正确思路：** 先明确允许范围为 `count > 0`，因此拒绝条件是 `count <= 0`；值不合法时使用 `ValueError`。
- **掌握情况：** 已修复并通过有效输入、`0` 和负数测试；后续需要在其他数量/范围校验题中复查。

### 2026-09-17 — 捕获异常后仍继续执行

- **问题：** 输入成绩数量或成绩内容错误时，只输出友好提示，不显示 traceback，并结束当前程序流程。
- **我的做法：** 在局部 `try/except` 中捕获 `ValueError`，使用 `print()` 输出提示，但没有阻止后续代码继续执行。
- **错误：** 数量输入为 `abc` 时，`count` 没有成功赋值却继续使用，产生 `UnboundLocalError`；数量输入为 `0` 时继续统计空列表，工具函数再次抛出 `ValueError`。
- **原因：** `except` 只负责接住异常并执行处理代码；执行完 `except` 后，程序默认继续执行后面的语句。`print()` 不会自动结束函数或程序。
- **正确思路：** 明确异常处理边界：要么在更外层统一捕获并结束流程，要么在当前函数处理错误后明确结束当前流程；不能让无效数据继续进入后续逻辑。
- **掌握情况：** 本次范围内已掌握；已独立加入 `return`，并通过数量输入 `abc`、数量输入 `0`、成绩输入 `abc` 和正常输入测试。
- **复查任务：** 在新的“必须大于 0”的数量参数练习中，独立设计 `raise`、`except` 和结束流程，并解释为什么异常处理后不能让无效数据继续执行。

### 2026-09-17 — `with` 语句与 `json.load()` 参数使用错误

- **问题：** 将统计报告写入 JSON 后，再从文件读取并打印。
- **我的做法：** 初次写成 `read_report = with json_path.open(...) as file:`，并调用 `json.load()` 时没有传入文件对象。
- **错误：** 把 `with` 当成可以放在赋值右侧的表达式；`json.load()` 缺少要读取的文件对象。
- **原因：** `with` 是独立的资源管理语句，代码块内部才能使用打开的文件对象；`json.load(file)` 才能明确从哪个文件读取 JSON。
- **正确思路：** 使用 `with ... as file:` 打开文件，在代码块内部执行 `read_report = json.load(file)`；`json.dump(data, file)` 与 `json.load(file)` 分别对应写入和读取。
- **掌握情况：** 本次范围内已掌握；已修正并实际生成、读取 JSON 文件，结果与原统计字典一致。
- **复查任务：** 在 t12 中从 JSON 文件读取成绩列表，并把读取结果传给统计函数。

### 2026-09-18 — 数据类型校验条件方向错误与异常未捕获

- **问题：** 读取 JSON 后，要求只允许非空成绩列表进入统计函数。

- **错误：** 合法列表被错误拒绝；修正条件后，非列表或空列表会产生未捕获的 `ValueError` 和 traceback。
- **原因：** 没有把“拒绝条件”从自然语言准确转换为 `not isinstance(...)`；也没有同步检查主动抛出的异常是否有对应的捕获分支。
- **正确思路：** 先判断 `not isinstance(scores, list)`，再判断列表是否为空；对校验失败使用 `ValueError`，并在主流程中捕获它，提示错误后结束，不调用统计函数。
- **掌握情况：** 本次已修复；正常路径通过运行和编译检查，异常分支已通过代码审查，后续需要在元素级校验中复查条件方向和异常捕获。

### 2026-09-18 — `isinstance()` 类型参数误用列表

- **问题：** 校验成绩列表中的每个元素是否为整数或小数。
- **我的做法：** 把多个允许类型写成 `isinstance(score, [int, float])`。
- **错误：** 运行时产生 `TypeError: isinstance() arg 2 must be a type, a tuple of types, or a union`。
- **原因：** `isinstance()` 的第二个参数要求是单个类型，或由类型组成的元组；列表不是合法参数。
- **正确思路：** 使用 `isinstance(score, (int, float))`；如果判断结果为假，抛出 `ValueError`，阻止无效元素进入统计函数。
- **掌握情况：** 已修复并通过正常运行和编译检查；后续在多类型校验场景中复查 API 参数要求。

### 2026-09-18 — 混淆 JSON 解析阶段与数据校验阶段

- **问题：** 为 JSON 文件增加格式错误处理，并区分解析失败和数据内容无效。
- **我的做法：** 初始认为格式错误会继续执行到 `if not isinstance(scores, list)`，在那里产生自己抛出的 `ValueError`。

- **掌握情况：** 已理解并完成代码实现，待后续异常变式复查。
