## 代码审查标准

后续代码审查按“大厂工程实践”分层执行，但不把生产项目的复杂要求强行套在基础练习上。

### 练习代码

1. **需求正确性（P0）**：输入、处理、输出是否符合要求；边界条件是否正确。
2. **可读性（P1）**：变量和函数命名准确，控制流程清楚，避免误导性写法。
3. **基本健壮性（P1）**：类型转换、变量生命周期、空数据和明显异常是否考虑；超出当前任务范围的问题单独标注，不擅自扩大任务。
4. **验证意识（P1）**：是否有代表性测试，尤其是边界值；能否根据实际运行结果判断正确性。
5. **风格规范（P2）**：格式统一、拼写正确、避免硬编码和不必要的重复。

5. `F05-AI应用前端整合`：将 React/Next.js 前端与 FastAPI、LLM、RAG 或 Agent 后端连接，处理流式输出和交互状态。

### 需求实现的优雅性

在正确性通过后，单独审查实现是否是当前需求下的合适解法：

1. **需求映射**：代码结构是否自然对应需求步骤，是否存在无关逻辑。
2. **抽象层级**：是否既没有把简单问题写得过度复杂，也没有把应该复用的逻辑散落重复。
3. **数据流设计**：数据从输入到处理再到输出是否清楚，是否存在不必要的中间状态或重复保存。
4. **语言习惯**：是否合理使用 Python、JavaScript 或 TypeScript 的常见表达方式，而不是机械堆砌语法。
5. **扩展与修改成本**：需求发生小幅变化时，是否只需要改动一个清晰的位置。
6. **学习目标平衡**：练习阶段可以为了训练循环、列表等知识点保留显式实现；不能因为“更短”就跳过本次要练习的核心能力。

“优雅”不是代码越短越好，而是在满足需求、符合当前学习目标的前提下，复杂度、可读性和扩展性之间取得合理平衡。
