## 当前记录

### 2026-09-16 — `input()` 字符串与整数直接比较

- **问题：** 读取分数并判断是否达到 60 分。
- **我的做法：** 直接使用输入结果参与 `score > 60` 比较。
- **错误：** 运行到条件判断时，字符串和整数不能直接比较，产生类型错误。
- **原因：** `input()` 返回字符串，即使输入内容看起来是数字，也不会自动变成整数。
- **正确思路：** 先明确输入数据类型，再把输入转换成整数，并使用转换后的结果参与比较。
- **掌握情况：** 需要复习（在提示后已修复，尚未做无提示变式复查）。
- **复查任务：** 独立完成一个需要输入整数并进行数值判断的变式题。

### 2026-09-16 — 变量未定义导致 `NameError`

- **问题：** 将转换后的分数用于条件判断。
- **我的做法：** 修改输入代码后，在条件中继续使用 `score`，但没有确保转换结果保存到 `score`。
- **错误：** 第 3 行使用 `score` 时产生 `NameError: name 'score' is not defined`。
- **原因：** 变量名在赋值处和使用处不一致，或者根本没有在使用前完成赋值。
- **正确思路：** 检查变量的赋值位置、变量名拼写和使用顺序；使用前必须先定义该变量。
- **掌握情况：** 需要复习（已根据 traceback 定位并修复，待变式复查）。
- **复查任务：** 编写一个包含两个变量的短程序，检查每个变量是否先赋值后使用。

### 2026-09-16 — `>` 与 `>=` 的边界条件混淆

- **问题：** 分数达到 60 时应输出 `及格`。
- **我的做法：** 初始使用 `score > 60`。
- **错误：** 输入 `60` 时输出了 `不及格`。
- **原因：** `>` 不包含等于，无法表达“大于或等于”的要求。
- **正确思路：** 把自然语言中的“至少、达到、大于或等于”对应为 `>=`，并专门测试边界值 60。
- **掌握情况：** 需要复习（已修复且通过 59、60、85 测试，仍需在变式题中确认）。
- **复查任务：** 独立完成一个包含“达到某个阈值”要求的判断题，并测试阈值本身。

### 2026-09-16 — 函数参数未使用与职责混淆

- **问题：** 将成绩转换和校验逻辑拆分到 `check_input_score()` 函数中。
- **我的做法：** 函数虽然接收了 `raw_score`，但仍在函数内部调用 `input()`；发生错误时直接 `print()`，没有把异常交给主流程处理。
- **错误：** 函数参数没有真正参与处理，函数和主流程的职责边界不清晰，后续难以复用和统一处理输出。
- **原因：** 一开始把“获取输入、验证数据、显示错误”全部混在函数中，没有区分函数返回值、异常和主流程输出的作用。
- **正确思路：** 主流程负责获取输入和输出；校验函数只接收参数，完成转换和验证，合法时返回整数，不合法时使用 `raise ValueError(...)` 抛出异常。
- **掌握情况：** 已根据提示修复并通过六组输入测试，仍需通过导入场景复查 `main()` 和入口判断。
- **复查任务：** 导入 `t08_safe_score_input.py` 时，确认 `main()` 不会自动执行。

## 档案维护策略

- 只保留具有复习价值和迁移价值的错误模式。
- 同一根因的多个表现合并为一条，普通拼写、环境偶发问题和已无复习价值的细节不长期保留。
- 每完成约 3～5 个模块，检查一次：已稳定掌握的错误可压缩为一句复查提示，仍反复出现或影响后续学习的错误保留完整记录。
- 具体发生过程可留在对应的每日或模块记录中，错误档案只保留后续复习真正需要的信息。

### 2026-09-17 — 条件方向和异常类名写错

- **问题：** 为动态录入的成绩数量增加“大于 0”校验。
- **我的做法：** 初次写成 `if 0 <= count`，并使用不存在的 `Value` 异常类。
- **错误：** 合法的正数也进入异常分支，随后产生 `NameError`；条件方向与需求相反。
- **原因：** 没有把自然语言“当数量小于等于 0 时拒绝”转换成对应的逻辑条件，也混淆了 `ValueError` 的完整类名。
- **正确思路：** 先明确允许范围为 `count > 0`，因此拒绝条件是 `count <= 0`；值不合法时使用 `ValueError`。
- **掌握情况：** 已修复并通过有效输入、`0` 和负数测试；后续需要在其他数量/范围校验题中复查。
- **复查任务：** 为另一个必须大于 0 的数量参数设计拒绝条件，并说明为什么不能写成相反方向。
