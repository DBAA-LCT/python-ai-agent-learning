# 错误档案

> 更新：2026-09-21。只保留会影响后续项目的错误模式；历史详细记录见 [调整前快照](历史归档/2026-09-21-调整前/错误档案.md)。
> “旧任务已修复”不等于稳定掌握；“待跨任务迁移”也不等于必须先逐项补考。以下观察随项目验证更新。

## 活跃错误模式

### 1. 变量绑定与名称一致性

- 历史：出现过赋值与使用名称不一致、异常后使用尚未赋值变量；旧任务已有修复记录。
- 当前待修复：[已归档的t25](Python/练习/历史归档/t01-t25/t25_score_summary.py)中，`sum(score >= 60 for scores in scores)`循环绑定的是`scores`，表达式却读取`score`；非空输入会报`NameError`，空列表返回`0`不能证明正确。
- 处理方式：由学习者统一当前元素的名称，用空列表、普通输入和边界值验证；本次文档调整未修改练习代码。
- 迁移观察：在新项目中能否根据 traceback 定位名称及赋值位置。一次笔误不直接判定基础未掌握。

### 2. 输入类型、拒绝条件与边界

- 历史：`input()` 结果未转换就与整数比较、`>` 漏掉等于、正数拒绝条件或 `isinstance()` 判断写反。
- 状态：对应旧任务已修复；t24 有独立完成阈值统计的局部证据，综合输入校验仍待跨任务观察。
- 处理方式：先写允许的数据与范围，再写拒绝条件；按任务选正常、边界和非法输入各一例。
- 迁移观察：在项目的数据导入或 API 参数校验中完成验证，不另开一串成绩判断题。

### 3. 异常发生位置与失败后的控制流程

- 历史：`try` 未包住真正失败的操作、`except` 打印后仍继续使用无效数据、混淆 JSON 解析失败与解析后校验失败。
- 状态：旧任务有修复记录；其中部分异常分支仅做过代码审查，不能统称全部运行通过。
- 处理方式：先定位可能失败的语句；失败后明确返回、重试或向上传播。需要分别处理时，将 `JSONDecodeError` 放在其父类 `ValueError` 前。
- 迁移观察：项目实际需要文件读取时，验证文件缺失、格式错误或无效内容中的相关失败路径。

### 4. 函数职责与导入副作用

- 历史：函数接收参数却重新 `input()`；从带顶层执行代码的脚本导入，导致重复读取或输出。
- 状态：t08、t13、t17 已有修复与入口/导入验证记录；t24 有参数和返回值的局部独立证据，跨业务拆分仍待观察。
- 处理方式：业务函数使用参数、返回结果或抛出异常；交互流程放在入口，复用函数从其定义模块导入。
- 迁移观察：在一个真实功能中拆出可复用处理函数，确认导入不会自动启动交互；无需再从零刷函数语法。

### 5. 数据更新时遗漏关联状态

- 历史：成绩下降后未同步将 `passed` 改为 `False`，派生字段可能保留旧值。
- 状态：旧任务已修复；t22 有正反分支运行记录，但不能据此断言已独立掌握所有状态更新问题。
- 处理方式：明确哪些字段由其他字段推导；修改源数据时重新计算，或在读取时计算以免重复保存。
- 迁移观察：项目出现状态更新时，验证两个方向的变化；无需专门再排字典字段微练习。

## 已纠正的教练误判

- 原记录把 `f"{record.get("name")}"` 一概判为引号冲突和语法错误，此结论不适用于当前 Python 3.14。
- Python 3.12 的 [PEP 701 官方说明](https://docs.python.org/3.12/whatsnew/3.12.html#pep-701-syntactic-formalization-of-f-strings) 已允许 f-string 表达式复用外层引号；本机 Python 3.14.4 最小运行验证正常输出 `Alice`。
- 撤销仅由“内外同引号”推导出的语法薄弱项及补考要求。不同引号仍可作为可读性或旧版本兼容选择。
- 历史局限：本次只验证该写法，不据此断言 t19、t21 当时完整代码没有其他错误；历史原记录保留在快照中。
